# rd-mynotes：照用户的逻辑整理用户自己的笔记

一句话：**这是用户的笔记，不是 agent 的报告。** 用户的手写稿是骨架，agent 只把骨架之间缺的细节补上；拿不准就问，不替用户做决定。dashboard 里的 wiki、lab 推导、文献卡片是补细节时查的素材，不是要搬进来的内容。

## 先读

1. `mynotes/README.md`（文件夹约定、颜色）和 `mynotes/notation.tex`（这份笔记记号的唯一来源）。
2. 文风：Project Notes 根目录的 `我的笔记文风.md`（各课题共用）和 `mynotes/STYLE.md`（这个课题特有的）。路径看 `rd mynotes status <课题目录>` 输出里的 `style`。
3. 要放进去的那一节和前后相邻的节：上下文的记号、编号、语气。
4. 要补细节时再查 dashboard：`wiki/`、`labs/*/notes.md`、`references/cards/`。

还没有 `mynotes/`：`rd mynotes init <课题目录> --title "…" --author "…"`（标题问用户；pdflatex 编不了中文标题）。

## 一批增补

一份手写稿（或用户一次给的一段内容）是一批。一批只动正文里的一处，加上 notation.tex 登记新记号、refs.bib 加文献。

### 1. 定位置

用户说了放哪就放哪。没说时看内容，提议"接在第几节之后"或"新开一节，标题、文件名 `sections/NN-slug.tex`"，用户点头再写。新节在 `main.tex` 里按顺序 `\input`，`\section` 后紧跟 `\label{sec:…}`。

### 2. 照录（黑色）

- 逐句录入用户写的文字、公式和推导顺序。手绘的图先写 `\cmt{此处原稿有图：……}`，问用户要不要画、怎么画。
- **用户的话留在正文里**，尤其是用户自己起的说法、结论句、每节开头结尾"接下来做什么"的交代。反面例子：一份手写稿结尾的 "kinetic energy driven pairing"，改写后全文找不到了，换成了 agent 自己的类比。可以把英文改通顺、修语法，意思和用词选择不换。
- 看不清的字或符号：按最可能的读法录入，后面加 `\cmt{原稿看不清：读作 … ？}`。
- 用户写错的地方（符号、因子、推理）：不改用户的，加 `\cmt{…}` 说你认为哪里不对、为什么；你的写法放进清单让用户选。

### 3. 补细节（橙色）

只补四类，句内用 `\orange{…}`，整段或带行间公式的用 `\begin{orangeblock}…\end{orangeblock}`：

1. **中间步骤**：用户从一个式子跳到下一个，补出中间几行；等号上方的代换说明照用户的习惯写。
2. **衔接**：句子之间、公式之间缺的连接词和过渡句。
3. **定义**：用到了但上下文没定义的符号，补一句定义，并登记进 notation.tex。
4. **引用**：对前文公式（`\eqref`）、小节（`\secref`）、文献（`\cite`）的引用。

**不补**，写进清单「没写进去的建议」由用户决定：新的论证或证明思路、类比和物理图像的延伸、新的小节或例子、调换用户的顺序、用户没写的结论、推广到更一般的情形。宁可少补。

每处补充的来源写在紧挨着的 tex 注释里，不进 PDF：`% src: 前文 Eq.~(3)`、`% src: labs/01-…/notes.md §2.3`、`% src: 卡片 2104.14257`。从 dashboard 搬来的推导先换成笔记的记号、验算过再写。

### 4. 记号

- 正文用到的记号都要在 notation.tex 登记：`\notation{符号}{含义}{首次定义处}`。这一批新出现的，按用户手写稿的写法登记；记号专用的宏也定义在那里。
- 用户的写法和 notation.tex 已有的冲突（同一个量两种写法、同一个符号两种含义）：不自己统一，用 `\cmt{}` 问。
- notation.tex 是 dashboard `wiki/notation.md` 的上游（AGENTS.md 第 3 节）；不为了迁就 dashboard 改笔记的记号。

### 5. 验算

补的中间步骤都要验算（sympy、Mathematica 或数值），脚本放 `mynotes/checks/`。验算过程和结果不写进正文，只在清单里列出验算了哪些式子。

### 6. 编译和交付

```
rd mynotes build <课题目录>     # 无错误、无未定义引用才交；没装 TeX 的机器上会报错，到装了 TeX 的机器上编译
rd mynotes redline <课题目录>   # 和上次接受的版本（git HEAD）比；第一批没有旧版本，跳过
```

在 `mynotes/review/YYYY-MM-DD-slug.md` 写对照清单：

```markdown
---
title: <这一批讲什么>
status: pending
date: YYYY-MM-DD
inputs:
  - mynotes/inbox/<原稿文件名>
---
# <这一批讲什么>

## 放在哪
## 对照表
| 原稿 | 正文 |
|---|---|
| 第 1 页第 1–5 行 | Sec. II A 前两段，Eq. (12)–(13) |
## 补了什么
- Eq. (14) 前两步：把 Eq. (12) 代入 …（src: …）
## 没写进去的建议
## 问你的（和正文里蓝色的一一对应）
## 记号变动
## 验算
```

对照表要覆盖原稿的每一部分：用户据此确认没有漏掉、没有调换顺序。交给用户时一句话说清：放在哪、补了几处、有几个问题；PDF、红线版和清单在网页「我的笔记 › 正文」都点得开。

### 7. 接受

用户答完问题、同意这一批以后：

1. 按用户的回答改正文，删掉对应的 `\cmt{}`；用户否决的补充直接删掉。
2. `rd mynotes accept <课题目录>`：还有 `\cmt` 会拒绝；通过后橙色标记去掉变成正文、清单里列的原稿从 `inbox/` 移到 `originals/`、清单标 accepted，并重新编译。
3. 在课题目录 git commit（只提交 `mynotes/` 和 `log.md`）。
4. 这一批来自某条批注时：`rd mine <课题目录> --id <批注 id> --in-notes <那一节的 label>`。

## 批注收进正文

用户说"把这条批注整理进笔记"：批注原文当作手写稿，走上面的流程；清单「放在哪」写明来自哪条批注。批注本身不删。

## 学文风

用户给旧笔记当样本时：读完，在 `我的笔记文风.md` 的「样本」下登记（路径、是什么、用户让学哪些方面），在「规矩」下写出从中总结的规矩，每条注明来自哪份样本。用户说只参考某些安排，就只总结那些。和已有规矩冲突时问用户。写完把新增的规矩列给用户看。只属于这个课题的规矩写进 `mynotes/STYLE.md`。

## 不做

- 用户没让写时，不往正文写任何东西；lab 收尾、wiki 改写都不碰 `mynotes/`。
- 不改写已经接受的段落；发现前文有错，用 `\cmt{}` 指出，等用户决定。
- 不概括、不删减用户的内容；审计过程和验证细节不进正文。
- 不改 `preamble.tex` 的颜色和版式（用户的母版）。
