# rd-notes：网页可读的推导与讲解笔记

一句话：**写作单位是"一步推导"，不是"一段结论"**；你在带读者复现推导，不是向审稿人压缩结果。文体和纪律继承 baby-steps-report，交付物从双语 LaTeX/PDF 改成课题里的中文 markdown。

## 产物

```
labs/NN-slug/
├── report.md       薄层摘要（不是本 skill 写；见 rd-lab 的写作步）
├── notes.md        本 skill 的产物：完整推导、分析、验证；一个 lab 一份
├── fig/            图（PNG/SVG），notes.md 与 report.md 共用
├── scripts/        验证脚本，文件头注明验证的是哪一节哪个公式
└── results/        适合放进项目的小结果（csv/json）
```

notes 很长、而且有几个能独立阅读的问题时，才拆成 `notes/index.md` + 分章文件；`report.md` 的 `notes:` 字段指向唯一入口。不要同时维护两份内容相同的 notes。

## 流程

1. **输入确认**：用户 notes（记号最高权威）、知识边界（用户声明"我知道 X"之外的一切现场推导；没声明就按本科量子力学与统计物理）、要回答的问题清单。
2. **记号**：对照 `wiki/notation.md`，新记号先登记再用。
3. **问题链提纲**：每节回答一个问题，标题就是问题或判断（"为什么单纯的 $K\neq1$ 不会打开 gap？"），不是名词短语（"模型与方法"）。列出易混淆概念簇，安排在计算前拆开。
4. **动笔前的分歧检查**：任务书 ↔ 用户 notes/PROJECT.md ↔ 你的路线，三方对照。有分歧：交互会话里用 AskUserQuestion 问（裁决同时落盘到 `discussion/`）；无人值守时写 discussion、lab 状态改 `waiting_answer`、结束运行。没有分歧也要在 notes 开头写一句"检查过 X、Y、Z，没有分歧"。
5. **写作**（细则见下）。
6. **验证**：关键代数用 sympy/numpy 或 Mathematica 复核，脚本落盘 `scripts/`；正文推导必须独立成立，脚本只是确认，以脚注或节末一句话出现（"式 (3.2) 已由 `scripts/check_x.py` 验证到 $10^{-12}$"）。
7. **自审**：对照文末清单，任何一条不过就改。

## 写作细则

- **结论先行**：notes 第一节是编号的结论清单（"我先把结论写清楚"），每条一到三句加关键公式，用户问的每个问题在这里有直接回答。
- **每节是一个闭环**：问题 → 拆混淆 → 本节新定义 → 逐步计算 → 困惑处的例子或极限检验 → 节末结算（严格得到了什么、用了什么假设、还没得到什么）→ 路标句（下一节为什么是它）。
- **三拍节奏**：动机句 → 行间公式 → 意义句。相邻结论之间没有断桥，读者不动笔能跟上。
- **禁语**："直接展开得到""容易验证""显然""类似地可得""经过直接计算""标准推导给出"。写到就停下，把被遮住的步骤拆开。
- **首次出现即定义**：每个符号、每个名词，首次出现处交代清楚，即使以前的报告定义过。
- **专有名词中英并列**：专有名词、方法名、物理量名首次出现写「中文（English）」，如 稳定子态（stabilizer state）、相对熵（relative entropy）；读者可能只认识英文。
- **文字论断马上跟公式**。
- **假设记账在现场**："到这里严格得到的是 X；若要进一步声称 Y，还必须加入假设 A。"
- **不自造代号**。
- **数值结果**：先说趋势和量级，再给代表值和误差，完整表放 `results/` 并链接；影响主结论的未收敛、待重算、不可靠点必须写在相关结论旁边，不能只藏在方法节。
- **图**：每张图的图注写"看哪里 → 看到什么 → 说明什么 / 不能说明什么"，落到面板、曲线或标记（颜色、实心/空心）、参数区间或色带、眼睛该看到的形状；示意图标明是示意；拟合与数据分开。

## markdown 与公式

- 公式用 `$…$`、`$$…$$`（KaTeX）。多行用 `aligned`。要引用的公式用 `\tag{3.2}` 手动编号（按节号），正文写"由式 (3.2)"。不用自定义宏；课题常用符号的写法以 `wiki/notation.md` 为准。
- 章节用 `##`、`###`；网页会自动生成目录与锚点，`report.md` 用 `notes.md#节标题` 链接到小节。
- 定理、结论、警告用引用块加粗开头（`> **结论 3.1**`），不用 HTML。
- 表格只罗列可枚举的事实，不用表格代替论证。

## 按需导出

- **PDF**（用户要分享、打印时）：`pandoc notes.md -o notes.pdf --pdf-engine=xelatex -V CJKmainfont="PingFang SC" -V geometry:margin=2.5cm --toc`；图路径相对 lab 目录，在 lab 目录里运行。导出后在 `report.md` 的「文件」列出并注明导出日期；notes 更新后 PDF 不自动重编。
- **英文版**（用户明确要求时）：另存 `notes_EN.md`，按内容重写而非逐字翻译，节号与公式号一一对应。
- 用户要求完全独立的双语 LaTeX 报告时，改用 baby-steps-report skill，PDF 放 `report/`，`report.md` 的 `notes:` 指向它。

## 自审清单

1. 开头是编号的结论清单；用户的每个问题都有直接、显著的回答。
2. 每节标题是问题或判断；节间有路标句；易混淆概念在计算前拆开。
3. 搜索禁语：每处要么删、要么紧跟完整步骤；每个"因此/所以"读者不动笔能跟上。
4. 每个符号、名词首次出现处有定义；文字论断后跟公式；记号与 `notation.md` 一致。
5. 关键结论旁写明严格程度与假设；反例或极限检验放在困惑发生处。
6. 数值结论旁有适用范围（模型、参数、尺寸、方法）与会改变判断的未完成检查。
7. 验证脚本落盘、能跑、头部注明式号；证据标签不进正文主线。
8. 图在 `fig/`，图注合格，坐标轴有标签和单位。
