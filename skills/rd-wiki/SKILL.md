# rd-wiki：当前理解的汇编

思路来自 Karpathy 的 LLM-wiki 模式：原始资料（文献、报告、讨论）只读不改；wiki 是 agent 编译出来的、带引用的、可以随时重写的"当前理解"。回答问题时先查 wiki，而不是每次重读所有原文。

## 三个操作

### ingest：把新资料编译进 wiki
触发：新卡片入库、lab 完成、讨论被消化。
1. 读新资料，列出它涉及的概念。
2. 每个概念：已有页就改写相关段落（不是追加一段"另外…"），没有就新建。
3. 每个论断都带引用：`（见 [[card:2104.14257]] 式 12）`、`（lab [[03-metric-bounds]] 报告 §2）`、`（讨论 [[2026-10-02-which-limit]]）`。链接目标写卡片 key、lab id、讨论 id 即可，dashboard 会解析。
4. 新结论与旧结论矛盾：不并列保留两种说法。改写成一种，并在「争议与未定」记录为什么改、旧说法来自哪。真正定不了的写 discussion。
5. `index.md`：新页加链接；「当前认识的一页总结」若受影响则改写。

### query：回答问题
用户或任务问到概念时，先读 `index.md` 找页，再读页，引用页里的出处作答。wiki 没覆盖的，去读原文，然后顺手 ingest。

### lint：定期体检
`rd doctor <课题目录>` 查断链和缺节。此外人工检查：同一概念两页（合并）、页面超过约 1500 字（拆分）、「争议与未定」里已经被后来的 lab 解决的条目（更新）、notation 不一致。

## 页面规范

- 文件名 = slug（英文或拼音短名），`title` 用中文全称；可以用子目录分组（`wiki/models/creutz.md`）。
- 每页 300–1200 字，一页只讲一个概念或一个结论。
- 记号严格用 `wiki/notation.md`；引入新记号必须先在 notation.md 登记。
- 公式用 `$…$`、`$$…$$`（KaTeX 可渲染）。
- **尽量配一张示意图**：放 `wiki/fig/<slug>-*.svg|png`，在「定义与公式」之前用 `![一句话图注](fig/xxx.svg)` 嵌入。格子、能带、相图、逻辑链、算符作用，这些画出来比写出来快。手写 SVG 或 matplotlib 都行，脚本放 `wiki/fig/src/`。

## 页面模板

```markdown
---
title: <概念中文名>
tags: []
updated: 2026-10-02
sources: [card:2104.14257, lab:03-metric-bounds]
---

# <概念中文名>

一段话定义：它是什么，在本课题里为什么重要。

![示意图的一句话图注](fig/<slug>-schematic.svg)

## 定义与公式
（课题记号）

## 我们知道什么
- 结论 1（出处）
- 结论 2（出处）

## 与其他概念的关系
[[概念 A]] 决定了…；与 [[概念 B]] 的区别在于…

## 争议与未定
- …（为什么没定，等哪个 lab/讨论）

## 文献
- [[card:…]]：它贡献了什么
```

## notation 变更的同步

用户改了 `wiki/notation.md` 后：grep 所有 wiki 页和卡片中受影响的符号，逐页改写；在 `log.md` 列出改了哪些页；旧 PDF 不重编，只在对应 `report.md` 顶部加一行说明。
